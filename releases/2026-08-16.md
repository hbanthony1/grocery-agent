# Release Notes — Season 2
**Date:** August 16, 2026  
**Branch:** beta → master (PR #1) + hotfixes

---

## New features

### Dashboard landing page
The app now opens to a dashboard instead of jumping straight into planning. Dinner Tonight shows tonight's meal at a glance with a quick-change button. The This Week grid shows all 7 days, clickable to edit any night. Expiring pantry items surface automatically so nothing goes to waste.

### Login & multi-user accounts
The app now has a login screen with registration, invite-code gating for new accounts, and per-user data isolation. Each user gets their own recipes, pantry, prefs, and meal history. Includes password reset and an Account tab in Settings.

### Weekly summary email
Every Sunday morning a summary email goes out with the full dinner plan (all 7 days, including weekends and Leftovers nights) and any Google Calendar events for the week. Set up via `python setup_reminders.py`.

### Dinner reminder emails
A daily 3:30pm reminder email shows tonight's dinner with the full recipe — ingredients and steps — so whoever is cooking can start prepping on time.

### Meal history & monthly AI summary
The app tracks the last 4 weeks of meals. A monthly Claude summary highlights patterns, variety gaps, and suggestions. Individual weeks can be deleted from the history panel.

### Training panel
A dedicated nav panel for marathon training config. Set race name, date, training phase, long-run day, and mileage. The app factors this into meal planning and adds athlete-specific items (gels, electrolytes, recovery food) to the cart.

### Leftovers double-batch
When a night is marked Leftovers, the app offers to double the previous night's recipe so there's enough. Doubles the ingredient quantities automatically.

### Cart guard
Prevents accidentally wiping a cart that's already been built. Prompts to confirm before regenerating.

### Prep guide on dashboard
After planning, a "generate prep guide" button appears on the dashboard. Claude produces a personalized Sunday afternoon prep checklist so weeknight dinners are faster.

### Occasions planner rebuild
The Holiday/Occasions tab now has structured flows for travel (road trip, flight, hotel stay) with auto-generated packing lists, and a hosting flow for when company is coming.

### Demo mode
Run `python server.py --demo` (or `run_demo.bat`) to launch an isolated sandbox on port 5001 with preloaded data. Useful for showing the app without touching real data. Includes a scenario picker for Sunday pre-order, post-order, and mid-week states.

### Visual redesign
New deck aesthetic throughout — tighter spacing, card-based layout, updated color tokens. Appearance settings consolidated into a single tab (replaces the nav theme toggle).

### Pantry sort by expiration date
A sort toggle button sits next to the pantry search bar. The default view is A–Z (alphabetical, with expired and soon-to-expire items pinned to the top). Click "sort: A–Z" to switch to "sort: expiry" — items ordered by exact expiration date, soonest first, with undated items at the bottom.

### PWA & deployment
The app installs as a Progressive Web App on mobile. Docker and Procfile added for hosted deployments. `WALMART_PRIVATE_KEY_CONTENTS` env var supported as an alternative to the PEM file for cloud environments.

## Bug fixes

| # | What was broken | Fix |
|---|----------------|-----|
| 1 | Pasting a recipe URL crashed with `name 'client' is not defined` | Added missing `anthropic.Anthropic()` instantiation in `import_recipe_from_url()` |
| 2 | Weekly summary email showed Sunday, Saturday, and Leftovers nights as blank | Email agent now reads from `prefs.lastWeekMeals` (all 7 days) instead of `meal_schedule.json` (Mon–Fri reminders only) |
| 3 | Dashboard "Dinner Tonight" showed "No dinner planned yet" after a completed planning session | `/week-glance` endpoint referenced undefined `week_monday_iso`, crashing on every call and silently returning empty data |
| 4 | Dashboard "This Week" grid showed nothing | Same root cause as #3 — the empty response left `data.days = []` so the grid never rendered |
| 5 | Registering after deleting `users.json` still required an invite code | The login page's probe request was registering a real `__probe__` account, immediately triggering the invite-code requirement for all subsequent registrations |
